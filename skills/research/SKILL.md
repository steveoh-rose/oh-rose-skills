# Research

Pick the lightest method that answers the question and supports the decision.

## Process

1. Write the question in one sentence.
2. Write the decision the answer will change. If none, skip the research.
3. Check access: real users, proxies, or neither.
4. Pick a method. Define signals before running anything.

## Methods

| Question | Method | Signals |
| --- | --- | --- |
| How do others solve this? | Competitor and analogous research | Steps to complete, feature parity |
| Where do people struggle? | Support tickets, feedback | Volume by category, repeat contacts |
| Why do people adopt or leave? | User interviews | Motivations, mental models |
| What are the constraints? | Stakeholder interviews | Commercial, technical, timeline limits |
| No direct user access | Proxy interviews (sales, success) | Recurring friction, deal-breakers |
| What happens in real context? | Field study | Interruptions, tool switching, re-entry |
| How widespread is this? | Survey | Counts, segments |
| Which option is preferred? | Preference test | Split, reasons |
| Is purpose clear fast? | 5-second test | Purpose and action recall |
| Are labels findable? | Tree test | Correct destination, no backtracking |
| How do people group things? | Card sort | Agreement, cohesion |
| Is the first click right? | First-click test | Accuracy, time, distribution |
| Can people finish tasks? | Unmoderated prototype test | Completion, dead clicks, drop-off |
| Where and why do they hesitate? | Moderated prototype test | Assisted completion, critical incidents |

## Rules

- Prefer real users for usability. Say so when using proxies.
- Stakeholders give context, not usability evidence.
- Surveys show how many, not why.
- Metrics are evidence, not verdicts. State sample size and limits.
- Never invent findings, participants or quotes.

## Output

One page: question, decision, method, participants, task, signals, how to read the result.
