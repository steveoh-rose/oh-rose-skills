# Task or project

## Task
Known problem, established pattern, contained change.
- Move quickly into execution and prototyping.
- Reuse existing patterns.
- Validate in proportion.
- Skip heavy documentation.

Examples: fix an alignment bug, add a page from an existing template, tighten copy, add a focus style, swap an image.

## Project
High uncertainty, complex workflow, or 0-to-1.
- Structured discovery before committing to a solution.
- Assumptions and constraints made explicit.
- Several paths explored.
- Riskiest assumptions tested early.
- Impact on the existing product considered. The right people involved.
- Progress and success defined before building.

Examples: redesign navigation, new onboarding flow, a new interactive feature, a new tool.

## Quick test
1. Do I know exactly what done looks like?
2. Is there an existing pattern to reuse?
3. Can I undo it in minutes?

Three yes: task. Any no: consider a brief. Two or more no: project.

Do not write a brief for a small, well-understood task just to follow process.
